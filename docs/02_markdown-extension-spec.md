# 提词器 Markdown 扩展规范 v1

本规范定义提词器编辑器中的两类特殊内容：

1. **Stage Cue 舞台提示**：提醒说话的人怎么演、怎么停、看哪里。
2. **Cue Marker 场记标记**：方便 retake、跳段、导演控制、后期定位。

它们都不是普通口播文本，但作用不一样。

---

## 1. Stage Cue：舞台提示

Stage Cue 用来提示演讲者做动作，比如：

- 看镜头
- 停顿
- 切屏幕
- 放慢语速
- 强调这句话
- 展示产品页面

它可以绑定在一句口播文本上。

---

### 1.1 绑定文本的舞台提示

原始文本：

```markdown
这是一个重点词语
```

加上舞台提示后的 Markdown：

```markdown
:stage[这是一个重点词语]{cue="look-camera" label="看镜头"}
```

编辑器渲染效果：

```text
这是一个重点词语
        ↳ 看镜头
```

这个效果很好，因为它清楚表达了：

- “这是一个重点词语”是要说出来的内容。
- “看镜头”是给演讲者看的提示。

---

### 1.2 更完整的渲染效果

如果提示比较重要，可以这样显示：

```text
这是一个重点词语
        ↳ 看镜头 · 重点
```

对应 Markdown：

```markdown
:stage[这是一个重点词语]{cue="look-camera" label="看镜头" level="important"}
```

如果有持续时间：

```text
这是一个重点词语
        ↳ 看镜头 · 2s
```

对应 Markdown：

```markdown
:stage[这是一个重点词语]{cue="look-camera" label="看镜头" duration="2s"}
```

---

### 1.3 独立舞台提示

有些提示不绑定某一句话，而是单独插在文稿中间。

比如停顿：

```markdown
::stage[pause]{label="停顿" duration="1.5s"}
```

渲染为：

```text
        ↳ 停顿 · 1.5s
```

完整示例：

```markdown
今天我们先看一个问题。
::stage[pause]{label="停顿" duration="1.5s"}
为什么 AI 看起来像是在思考？
```

渲染为：

```text
今天我们先看一个问题。
        ↳ 停顿 · 1.5s
为什么 AI 看起来像是在思考？
```

---

### 1.4 块级舞台提示

如果提示内容比较长，比如导演提示、录屏提示、产品演示提示，用块级格式。

```markdown
:::stage{cue="demo-screen" label="切演示画面"}
打开产品后台首页。
鼠标停在「数据看板」区域。
不要滚动太快。
:::
```

渲染为：

```text
        ↳ 切演示画面
          打开产品后台首页。
          鼠标停在「数据看板」区域。
          不要滚动太快。
```

## 2. Cue Marker：场记标记

Cue Marker 不是动作提示。

它的作用是给文稿插入一个特殊定位点，方便：

- retake
- 跳段
- 导演控制
- 后期剪辑定位
- 现场场记备注
- 分段拍摄

它不绑定原文，只是在文稿的某个位置插入一个 marker。

---

### 2.1 独立 Cue Marker

推荐用这种格式：

```markdown
::marker[M001]{type="retake" label="重录点" note="从这里开始重录"}
```

渲染为：

```text
◆ M001 · 重录点
  从这里开始重录
```

完整示例：

```markdown
我们刚才讲完了第一个核心问题。
::marker[M001]{type="retake" label="重录点" note="从这里开始重录"}
接下来进入第二部分。
```

渲染为：

```text
我们刚才讲完了第一个核心问题。
◆ M001 · 重录点
  从这里开始重录
接下来进入第二部分。
```

---

### 2.2 行内 Cue Marker

如果希望 marker 插在一句话中间，也可以用行内格式。

```markdown
这是第一部分的结尾。:marker[M002]{type="jump" label="跳段点"}接下来进入第二部分。
```

渲染时可以显示成：

```text
这是第一部分的结尾。 ◆ M002 · 跳段点 接下来进入第二部分。
```

不过产品里建议优先使用独立行 Marker，因为更像场记板，更清楚，也更方便点击跳转。

---

## 3. 两者的核心区别

### Stage Cue 是“怎么演”

```markdown
:stage[这句话很关键]{cue="look-camera" label="看镜头"}
```

渲染为：

```text
这句话很关键
        ↳ 看镜头
```

它的意思是：

> 说到“这句话很关键”时，要看镜头。

### Cue Marker 是“这里是一个控制点”

```markdown
::marker[M001]{type="retake" label="重录点" note="从这里开始重录"}
```

渲染为：

```text
◆ M001 · 重录点
  从这里开始重录
```

它的意思是：

> 这里有一个可以重录、跳转或导演控制的位置。

---

## 4. 推荐语法总表

| 类型 | Markdown 写法 | 用途 |
| --- | --- | --- |
| 绑定文本的舞台提示 | `:stage[文本]{cue="类型" label="显示名"}` | 给某句话加动作提示 |
| 独立舞台提示 | `::stage[pause]{label="停顿"}` | 插入单独提示 |
| 块级舞台提示 | `:::stage{cue="demo-screen"}...:::` | 插入长提示 |
| 独立场记标记 | `::marker[M001]{type="retake" label="重录点"}` | 插入跳段 / 重录 / 控制点 |
| 行内场记标记 | `:marker[M001]{type="jump" label="跳段点"}` | 在句子中插入控制点 |

## 6. 完整示例

### Markdown 源码

```markdown
# AI 到底是在猜，还是在想？
::marker[M001]{type="section" label="开场" note="可以从这里单独拍摄开场"}
今天我们讲一个很多人都好奇的问题：AI 到底是在猜，还是在想？
::stage[pause]{label="停顿" duration="1s"}
如果你问一个大模型：“苹果为什么会落到地上？”
它会给你一个看起来非常合理的答案。
:stage[但问题是，它真的理解重力吗？]{cue="look-camera" label="看镜头" level="important"}
::marker[M002]{type="retake" label="重录点" note="如果前面状态不好，可以从这里重新开始"}
这就是我们今天要拆开的核心问题。
:::stage{cue="demo-screen" label="切演示画面"}
切到屏幕，展示模型回答问题的界面。
鼠标停在回答第一段，不要滚动太快。
:::
很多时候，它不是在像人一样一步一步思考，而是在根据上下文预测下一个最可能出现的内容。
::marker[M003]{type="edit" label="后期点" note="这里加模型结构动画"}
```

```text

  可以从这里单独拍摄开场
今天我们讲一个很多人都好奇的问题：AI 到底是在猜，还是在想？
        ↳ 停顿 · 1s
如果你问一个大模型：“苹果为什么会落到地上？”
它会给你一个看起来非常合理的答案。
但问题是，它真的理解重力吗？
        ↳ 看镜头 · 重点
◆ M002 · 重录点
  如果前面状态不好，可以从这里重新开始
这就是我们今天要拆开的核心问题。
        ↳ 切演示画面
          切到屏幕，展示模型回答问题的界面。
          鼠标停在回答第一段，不要滚动太快。
```

## 7. 口播文本提取规则

这个对提词器很关键。

### 会被提取为口播文本的内容

普通文本会进入口播。

```markdown
:stage[这句话要说出来]{cue="look-camera" label="看镜头"}
```

其中，只有“这句话要说出来”会进入口播。

### 不会被提取为口播文本的内容

```markdown
::stage[pause]{label="停顿"}
::marker[M001]{type="retake" label="重录点"}
:::stage{cue="demo-screen" label="切演示画面"}
这里是导演提示，不是口播。
:::
```

## 8. 最终建议

Stage Cue：

> 给演讲者看的行为提示，可以绑定文本，也可以独立存在。渲染时用缩进箭头显示。

Cue Marker：

> 给导演、场记、后期和提词器系统看的控制点。渲染时用独立 marker 卡片显示。

最终底层格式推荐：

```markdown
:stage[口播文本]{cue="look-camera" label="看镜头"}
::stage[pause]{label="停顿" duration="1.5s"}
::marker[M001]{type="retake" label="重录点" note="从这里开始重录"}
```

最核心的一条渲染规则就是：

```text
口播文本
        ↳ 舞台提示
```

这个形态非常适合提词器，因为它不会打断阅读节奏，但演讲者一眼能看到提示。
