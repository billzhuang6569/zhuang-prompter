## 1. 产品目标

本产品是一个面向录播拍摄现场的网页提词系统。用户无需安装 App，只需通过浏览器创建或加入房间，即可在控制端管理文稿、版本、样式、播放策略和语音跟随，在播放端稳定显示提词内容。

MVP 的目标不是做一个功能很多的通用文稿工具，而是证明：

1. 一个房间可以稳定连接控制端和播放端。
2. 控制端和播放端都能控制滚动、速度、暂停和位置。
3. 播放端可本地执行滚动，远程场景不依赖逐帧同步。
4. 文稿以 Markdown 为源格式，支持 Stage Cue 和 Cue Marker。
5. 录播现场改稿可通过手动版本快照进行对比和回退。
6. 播放端可根据实时语音转写和文稿匹配自动推进。

## 3. 明确不做

MVP 不做以下内容：

- 不做观察视图。
- 不做导演视图。
- 不做独立手机遥控器视图。
- 不做直播级 Safe Edit Horizon。
- 不做多人同时编辑合并。
- 不做复杂 Git 分支。
- 不暴露命令行式 Git 概念。
- 不做完整账号体系。
- 不做移动端原生 App。
- 不做视频录制套件。
- 不做字幕工作台。

## 4. 用户角色

### 4.1 控制端用户

通常是导演、编导、助理或提词员。

核心任务：

- 创建房间。
- 管理文稿。
- 保存版本。
- 控制播放。
- 调整样式。
- 选择控制模式。
- 查看播放端状态。
- 必要时接管语音跟随。

### 4.2 播放端用户

通常是嘉宾面前的提词屏、扩展屏、iPad、电脑或远程浏览器设备。

核心任务：

- 显示干净提词画面。
- 本地执行滚动。
- 支持镜像和全屏。
- 可本地手动滚动或调速。
- 可作为语音源。
- 回传当前位置和设备状态。

## 5. 核心流程

### 5.1 创建房间流程

1. 用户打开网站。
2. 点击创建房间。
3. 系统生成房间号。
4. 用户进入身份选择页。
5. 用户选择控制端。
6. 系统进入控制端界面。

异常：

- 创建失败：显示重试按钮。
- 网络不可用：提示检查网络，允许本地草稿保存。

### 5.2 加入房间流程

1. 用户打开网站。
2. 输入房间号。
3. 系统校验房间是否存在。
4. 用户选择控制端或播放端。
5. 系统进入对应视图。

异常：

- 房间不存在：提示房间号错误。
- 房间已关闭：提示创建新房间。
- 连接失败：提示重试。

### 5.3 本地扩展屏提词流程

1. 同一台电脑打开两个浏览器窗口。
2. 两个窗口加入同一房间。
3. 主屏窗口选择控制端。
4. 扩展屏窗口选择播放端。
5. 播放端开启全屏和镜像。
6. 控制端导入或编辑文稿。
7. 控制端开始播放。
8. 播放端根据 Scroll Clock 本地滚动。

验收：

- 控制端调整速度后，播放端在可接受延迟内响应。
- 控制端暂停后，播放端停止滚动。
- 播放端全屏后没有多余 UI。

### 5.4 远程播放流程

1. 控制端创建房间。
2. 远程设备输入房间号加入。
3. 远程设备选择播放端。
4. 控制端推送文稿、配置和 Scroll Clock。
5. 播放端本地执行滚动。
6. 播放端持续回传真实状态。

验收：

- 远程播放端不依赖控制端逐帧同步。
- 控制端可看到播放端在线状态和当前位置。
- 网络短暂中断时，播放端保持最后画面。

### 5.5 版本保存与回退流程

1. 控制端编辑 Markdown 文稿。
2. 用户点击保存版本。
3. 系统允许填写版本说明。
4. 系统保存当前 Markdown、显示配置和 marker 信息。
5. 用户继续改稿。
6. 用户打开版本列表。
7. 用户选择历史版本进行对比。
8. 用户点击恢复。
9. 系统把历史版本恢复为新的当前草稿。

验收：

- 恢复历史版本不会删除旧版本。
- 版本列表能显示保存时间和说明。
- 对比视图能区分新增、删除和修改。

### 5.6 语音跟随流程

1. 控制端选择语音跟随模式。
2. 控制端选择一个激活语音源。
3. 语音源请求麦克风权限。
4. 系统开始实时转写。
5. 系统提取 Markdown 中的口播文本。
6. 系统将转写内容匹配到当前附近的文稿位置。
7. 播放端根据匹配结果推进滚动。
8. 控制端显示转写、当前位置和置信度。

验收：

- Stage Cue 和 Cue Marker 不参与口播匹配。
- 识别错误时不应大幅跳到远处。
- 控制端可随时暂停或手动接管。

## 6. 控制端需求

### 6.1 页面结构

控制端至少包含：

- 文稿编辑区
- 播放预览区
- 播放控制区
- 显示配置区
- 版本管理区
- 设备状态区
- 语音跟随区

### 6.2 文稿编辑区

功能：

- 粘贴 Markdown。
- 编辑 Markdown。
- 源码视图。
- 渲染预览。
- 快捷插入 Stage Cue。
- 快捷插入 Cue Marker。
- 快捷加粗、斜体、下划线、颜色。
- 保存草稿。

验收：

- 用户粘贴 Markdown 后不丢失基本格式。
- Stage Cue 和 Cue Marker 使用 `docs/02_markdown-extension-spec.md` 中定义的语法。
- 编辑后的内容可作为 Markdown 导出。

### 6.3 播放控制区

功能：

- 播放
- 暂停
- 回到开头
- 跳到上一段
- 跳到下一段
- 跳到 marker
- 倒退若干行
- 调整速度
- 手动滚动
- 重新同步

验收：

- 每次控制动作都生成可同步的状态更新。
- 播放端收到指令后在本地执行。
- 控制端最终显示播放端回传后的真实状态。

### 6.4 显示配置区

功能：

- 字号
- 行高
- 字体
- 文字颜色
- 背景颜色
- 边距
- 安全区
- 镜像
- Stage Cue 显示开关
- Marker 显示开关

验收：

- 镜像只影响播放端，不影响控制端正常阅读。
- 配置修改后可推送到播放端。
- 播放端重连后能恢复当前配置。

### 6.5 版本管理区

功能：

- 保存版本。
- 填写版本说明。
- 查看版本列表。
- 对比当前草稿与历史版本。
- 恢复历史版本。

验收：

- 版本保存对象以 Markdown 内容为核心。
- 恢复历史版本会产生新的当前草稿。
- 版本对比至少能显示文本级差异。

### 6.6 语音跟随区

功能：

- 选择语音源。
- 开启或关闭语音跟随。
- 显示实时转写。
- 显示当前匹配位置。
- 显示置信度。
- 人工接管。

验收：

- 同一房间同时只有一个激活语音源。
- 语音源断开后，控制端提示选择新语音源。
- 人工接管后，自动推进暂停或重新锁定当前位置附近。

## 7. 播放端需求

### 7.1 默认显示

播放端正式播放时默认只显示：

- 口播文本
- Stage Cue
- Cue Marker

不显示：

- 顶部导航
- 房间号
- 设置面板
- 多余按钮

### 7.2 本地执行

播放端必须本地执行：

- 滚动
- 速度计算
- 暂停
- 继续
- 跳转
- 手动滚动
- 语音跟随推进

验收：

- 播放端收到 Scroll Clock 后可独立计算当前位置。
- 控制端短暂失联时，播放端不立即清空或崩溃。
- 播放端回传真实位置。

### 7.3 简易控制

播放端可通过隐藏手势或快捷键唤出简易控制：

- 暂停
- 继续
- 手动滚动
- 调速
- 重新同步
- 开关语音跟随
- 退出全屏

验收：

- 简易控制默认隐藏。
- 唤出后不影响正式提词内容。
- 操作后状态同步回控制端。

### 7.4 设备可靠性

播放端应支持：

- 全屏提示
- 镜像提示
- 麦克风权限提示
- 断线提示
- 重连提示
- 防休眠提示

验收：

- 断线提示不应遮挡核心提词区域。
- 重连成功后恢复当前文稿、配置和播放状态。
- 无法获取麦克风权限时，允许继续作为普通播放端。

## 8. Markdown 文稿需求

### 8.1 源格式

Markdown 是用户感知的唯一文稿源格式。

要求：

- 粘贴输入 Markdown。
- 编辑保存 Markdown。
- 导出 Markdown。
- Stage Cue 和 Cue Marker 使用 Markdown 扩展语法。
- 不向用户暴露另一套结构化文稿格式。

### 8.2 运行时解析

系统可以在运行时从 Markdown 派生：

- 渲染树
- 口播文本
- Stage Cue 列表
- Cue Marker 列表
- 段落索引
- 滚动锚点
- 语音匹配索引

这些派生数据可以缓存，但不能替代 Markdown 源文稿。

### 8.3 滚动锚点

滚动锚点不应只依赖字符 offset。

推荐组合：

- marker ID
- 标题文本
- 段落序号
- 文本片段指纹
- 渲染行位置
- 当前版本 ID

验收：

- 插入少量文本后，系统仍能大致定位原有播放位置。
- marker 跳转优先使用 marker ID。
- 语音匹配优先在当前锚点附近搜索。

## 9. Scroll Clock 同步需求

### 9.1 定义

Scroll Clock 是控制端和播放端之间沟通滚动状态的核心对象。

它描述：

- 从哪里开始滚
- 以什么速度滚
- 从什么时候开始
- 当前是播放还是暂停
- 由哪一端发起

### 9.2 字段草案

```json
{
  "type": "scrollClock",
  "roomId": "room_123456",
  "scriptVersionId": "ver_001",
  "state": "playing",
  "anchor": {
    "type": "marker",
    "markerId": "M002",
    "fallbackTextHash": "hash_xxx"
  },
  "offsetPx": 0,
  "velocityPxPerSecond": 68,
  "issuedAt": 1780000000000,
  "sourceDeviceId": "controller_01",
  "sequence": 42
}
```

### 9.3 行为规则

- 控制端播放、暂停、调速、跳转时生成新的 Scroll Clock。
- 播放端本地根据 Scroll Clock 计算当前位置。
- 播放端定期回传真实位置。
- 新 sequence 的 Scroll Clock 覆盖旧 sequence。
- 文稿版本变化后，旧 Scroll Clock 不再直接套用，需要重新定位锚点。

## 12. LLM 排版体检

### 12.1 目标

LLM 排版体检不是 AI 改稿，不负责重写内容。它只帮助用户检查 Markdown 文稿中影响提词阅读的可读性和排版风险。

### 12.2 MVP 行为

1. 用户点击排版体检。
2. 系统把 Markdown 文稿发送给检查模块。
3. 检查模块基于内置规则和术语库生成建议。
4. 用户逐条确认或忽略。
5. 确认后的建议应用回 Markdown 草稿。

### 12.3 检查项

- 中英文空格。
- 固定英文词组。
- 常见缩写。
- 标点一致性。
- 括号成对。
- 超长句提示。
- 可能影响断行的长 URL。
- Stage Cue 和 Marker 语法错误。

### 12.4 明确不做

- 不自动重写表达。
- 不自动改变口播语义。
- 不替用户生成新段落。
- 不静默修改文稿。

---

## 13. 非功能需求

### 13.1 延迟

- 本地扩展屏模式下，控制端操作到播放端响应应尽量接近实时。
- 远程模式不承诺像素级跟手。
- 远程模式以播放端稳定显示和状态回传为优先。

### 13.2 可靠性

- 播放端断线时保持最后画面。
- 控制端断线后可重新进入房间。
- 房间状态应支持重连恢复。
- 文稿草稿应避免刷新丢失。

### 13.3 兼容性

MVP 优先支持：

- Chrome 桌面版
- Safari 桌面版
- iPad Safari
- iPhone Safari
- Android Chrome

### 13.4 安全

- 房间号应避免过短。
- 未加入房间的用户不能访问房间内容。
- 麦克风权限必须由用户主动授权。
- LLM 排版体检不应发送不必要的设备状态。

### 14.1 基础房间

## 15. 开发建议

第一阶段建议按以下顺序开发：

1. 房间创建与双视图加入。
2. Markdown 编辑、解析与播放端渲染。
3. Scroll Clock 和基础播放同步。
4. 控制端播放控制与播放端状态回传。
5. 版本保存、对比、回退。
6. Stage Cue / Cue Marker 完整支持。
7. 语音转写与语音跟随。
8. 断线重连和设备状态。
9. LLM 排版体检。

开发过程中以 `docs/00_productdesign.md` 作为产品原则来源，以本 PRD 作为功能拆解来源，以 `docs/02_markdown-extension-spec.md` 作为 Markdown 扩展语法来源。
