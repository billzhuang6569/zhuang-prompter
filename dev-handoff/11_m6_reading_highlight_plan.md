## 目标与范围

播放端中间视觉行包含哪些字符，控制端就为这些字符加底色，随换行、字号和视口变化更新。控制端横线仅从本地高亮位置推导。中央稿件区增加「编辑 / 完成」切换；完成态不允许修改，没有编辑光标，点击正文调整播放位置。移除当前字号放大的 200% 限制。

只修改 App 及其本机房间服务和测试，不涉及官网、外部部署代码、发版或用户数据迁移。沿用现有组件、字符索引和消息，不新增框架。既有文档阶段为 M0–M5，本项为下一阶段 M6，不表示旧阶段已重新验收。

## 产品决策

以下采用审阅记录中的产品确认，不再标为默认选项。

1. 已有稿件进入房间默认完成态；空稿进入编辑态。模式仅属于当前控制端，不引入全房间编辑锁。
2. **「完成」= 保存草稿并进入只读态**，取代中央区域独立的「保存草稿」按钮。历史版本的「保存」及版本备注继续保留；完成不自动生成历史版本。无改动时不重复保存、不清空时钟。
3. 有改动时沿用保存清空 ScrollClock 的现有语义，不自动续播。先处理输入法 composition 和待确认标记/注释，再提交最终文本；保存中防重复提交，失败保留编辑内容和编辑态。保存后不能拿旧修订的偏移直接套新稿。
4. **完成态点字后保持点击前的播放状态**：正在播放时，把目标字所在行放到中线，从那里以当前速度继续；暂停时定位后保持暂停。允许向前跳到尚未播到的位置，也允许后退。不得强制暂停或临时发一个暂停时钟。冻结态也不被点击解除。
5. 删除指示线拖动跳转，包括 `beginGuideDrag`、`beginGuideRailDrag`、移动/释放监听、悬停计时和 `role="slider"`。横线成为纯显示元素，不截获点字、滚动或选择事件。
6. 编辑态且本地稿与房间草稿一致时，**同样显示高亮和指示线**；有未保存修改时两者一起隐藏，显示「未同步」。撤销回同步稿或保存成功后，要等同修订的有效报告才能恢复。编辑态点击用于编辑，不跳转，也不自动抢滚动。
7. 多端仍以 `effectivePrimary()` 选出的主播放端为高亮事实来源。主端切换、离线或重连后等待有效新报告；无有效主端时不伪造高亮或定位成功。
8. 字号限制按 **200% 比例**移除，不换成新的 500% 或 1000% 产品上限。

## 开发方案

### A. 先缓存，再扩展现有字符范围

**第一步是缓存 `readingMap()`，不是先扩协议。** 按根元素、bundle 身份及 DOM 内容变化代次缓存 normalized 文本与 DOM 字符映射，供 `readingY()`、`readingAtY()`、行尾测量和点字反查共用。Lexical 替换节点后必须失效，不能只按 markdown 字符串判断。

- 在正文根观察 `childList/subtree/characterData`，或复用实际 editor update 通知；测量前处理尚未交付的 mutation，避免引用已脱离 DOM 的 Text 节点。卸载时清理观察器和引用。
- 高亮层放在正文根之外；不把每帧 `--playback-offset` 更新、覆盖层绘制、横线移动当成正文变化，否则缓存形同虚设或产生反馈循环。
- 字体、字号、容器宽高、镜像、全屏等只使布局几何失效；纯滚动使用内容坐标/当前变换，不每帧重建全文字符表。窗口 resize、ResizeObserver、字体加载完成均触发布局重算，暂停时也采样。

**第一阶段契约**沿用 normalized `textOffset`：

- `PlaybackState.currentAnchor` 保留 `type: "renderLine"` 和 `textOffset`，增加 `lineEndOffset`，含义为 `[textOffset, lineEndOffset)`。偏移仍是现有 normalized 字符串的 UTF-16 索引，不改语音索引的定义。
- `PlaybackState` 和 `ScrollClock` 增加 `draftRevision`，取实际渲染成功的 bundle 所属修订；新 RoomState 到达但正文未更新时不能提前使用新修订。版本标识使用真实保存版本或明确草稿标识，移除 `fixture_m1`。
- 从 `readingAtY()` 找到的行首向后测量该视觉行的行尾，利用缓存避免扫全文。混合粗体、代码字号按垂直重叠的行带归组，不要求所有字 rect 中点完全相等。镜像保持逻辑偏移顺序。
- 中线穿过正文行时选该行；落在行间选最近行，距离相同按稳定阅读顺序选择。空稿返回空范围，不能沿用上一稿的范围。
- 范围变化时立即复用 `playback.reportState` 上报，同一帧合并；原周期报告用于校准，不新增消息系统，也不逐帧广播 RoomState。
- 类型主要改 `domain/room/types.ts`，`shared/protocol.ts` 已引用相关类型，无独立新增字段时无需改动。本机服务仍须校验新增字段：安全整数、区间顺序、正文索引边界、修订、来源会话和序号；字段少不等于可以免校验。
- 控制端过滤旧主端、旧会话、旧修订和旧时钟报告。沿用现有 session/clientSeq/serverSeq/scrollClockId，不另建序列体系；缺行尾/修订的旧格式不得被标为精确同步。

### B. 同一个编辑器的编辑/完成态

`RichMarkdownEditor` 直接传 `readOnly`，完成态隐藏 caret、阻止内容修改，编辑态恢复编辑。编辑/完成切换不改变组件 key、不调用 `setMarkdown()` 重新灌稿、不切成 RenderBundleView，因此不增加双渲染或额外保活工程。

- 富文本的字体、间距、directive 样式保持一致。格式工具可禁用或隐藏内容但保留布局占位，避免正文因工具栏高度变化而跳动。
- 完成态拦截格式命令、原文输入、标记/注释弹窗及放置 caret 的自定义处理；原文入口只在编辑态可用。原文编辑后点完成回到富文本预览；这次视图转换与单纯编辑/完成切换分开验收，不声称既有原文切换会天然保留 Lexical 历史。
- 拆清完成回调的异步成功/失败契约，复用 `saveDraft()` 返回结果。composition 未提交或浮层有待确认内容时不能截断提交；先确认最终文本，再保存。无改动不发送保存请求。
- 保存新稿后保持暂停。仅当旧阅读位置能在新稿中明确对应时重新锚定；否则显示需要重新定位，不偷偷套旧偏移。新修订报告前隐藏旧高亮。
- 同步的编辑态和完成态使用同一套映射与覆盖层；编辑中保留选区和撤销重做，不因高亮变更改写 Lexical DOM。原文视图保留原有文本编辑职责，不把 normalized 偏移直接涂在 Markdown 源码上；返回富文本后恢复可信高亮。

### C. 点字定位必须覆盖正在播放的分支

完成态由 `caretRangeFromPoint` 或受支持的等价接口取得文本节点和偏移，反查缓存映射，发送现有 `Anchor{type: "renderLine", textOffset}`。需要几何回退时用 DOM Range，不加入新依赖。点在标点/emoji 上时，第一阶段吸附到同一正文块内最近的朗读字符；等距按阅读顺序，排除注释、标记和块外内容。此行为的精度边界见 D 节。

1. 点击瞬间读取最新已接受的时钟状态、`velocityPxPerSecond` 和 `controlMode`，生成新 scrollClockId，携带当前修订和目标 anchor。暂停时不引入速度，playing（含零速度）保留当前速度；不能用面板默认 speed 覆盖正在运行的实际速度。
2. **先执行语义定位，再决定是否推进。** 当前代码只有 paused 分支调用 `readingY()`；实施时让新点字时钟在 paused/playing 两种状态下都解析 anchor，通过 `offsetForReadingY()` 得到目标行居中后的 offset，然后重设 playbackPositionRef 与 scrollClockTimingRef 的 offset、receivedAt 和 key。
3. playing 从该本地单调时钟基点按原速度继续，paused/frozen 不推进。定位对每个新时钟只执行一次，不能因每个报告、React 重渲染或 ResizeObserver 回调重复拉回目标。速度变更沿用原有规则。
4. 不把目标位置伪装成旧 offset 的一次播放 tick，不发送临时暂停，不用比例估算覆盖精确 anchor。控制端以新 scrollClockId 对应的主端报告确认定位，旧报告不能拉回高亮。
5. 语音跟随时保留播放状态与当前速度，重置旧位置的语音目标，等待与新位置相符的后续匹配再调速；延迟的旧 transcript/match 不得立刻把位置拉回。复用现有语音匹配流程，不增加控制模式。
6. 只对单击/轻触正文执行跳转；拖选、滚动、空白和注释不误跳。保留基本键盘等价操作（如完成态选择正文后由可聚焦「定位到选区」按钮执行），不逐字增加 Tab 停靠点；额外快捷键可选。

### D. 高亮、非朗读字符边界与本地指示线

第一阶段用缓存的 `readingMap()` 把范围首尾映射到控制端 DOM，再用 Range `getClientRects()` 画底色覆盖层。中间的标点/空格/emoji 随 Range 覆盖；边缘尝试扩展到相邻非朗读字符，直到范围外的朗读字符或当前正文块边界。按允许的连续正文节点分别建 Range，不能让一个跨节点 Range 顺带覆盖其中的标记、注释或列表装饰。

**边缘扩展是待验证的近似，不是已经成立的精确保证。** 同一稿 `甲🙂乙`，播放端可能排成 `甲🙂 | 乙`，也可能排成 `甲 | 🙂乙`，其中 `|` 代表视觉换行。两种首行都只报告 normalized `[0,1)`，控制端无法仅凭该范围判断 emoji 属于哪行。纯标点/emoji 行没有 normalized 字符；点在跨行标点上吸附到最近朗读字符也可能选错行。原有 `readingMap()` 可用于首版，但其匹配成功不能证明这些边界正确。

- **分阶段策略：** 先实现并实测 normalized 行尾和边缘扩展；第一阶段不引入 `currentLine.ranges` 或 `Anchor.displayPosition`。把上述反例及重复文本、纯非朗读行纳入真实布局测试。
- 若测试发现错行、漏字、多涂或点选错位，进入有证据支撑的第二阶段，评审最小显示边界补充（原方案的块内 display-offset 仅为候选），再补实现。不能用「绝大多数情况正确」关闭完整实时对应的验收项。第二阶段不是本轮的功能代码授权。
- 代理对/组合字素边界不得被拆分；多个 normalized code unit 对应同一 DOM 字符时，画图和计数都去重。块内匹配不完整或稿件分叉时隐藏高亮与横线，并显示未同步，不用总高度比例补猜。
- 整个范围在控制端跨行时仍全部高亮；将高亮按本地视觉行归组，字素数量最多的一行决定横线中心，并列取阅读顺序较前的行。排除装饰及无宽度字符，不按像素宽度代替字符数。
- 覆盖层和横线均不参与排版、`pointer-events: none`；不篡改编辑选区。横线不读远端 lineFraction/比例/像素位置。控制端本地 resize/scroll 即可重算几何，不回传播放命令。
- 完成态按需自动跟随；编辑态、主动拖选期间不抢滚动。采用 DOM Range + 覆盖层支持 Safari 15，不依赖 CSS Custom Highlight API。

### E. 字号控件与重排

保留现场操作的滑块和 A+/A−，增加可编辑百分比数字框。滑块常用范围为 75%–500%，这是操作范围，不是产品上限；当前值超过 500% 时，滑块有效 max 至少扩至当前值，界面和数值保持一致。数字框与 A+ 可继续放大，不设新的固定产品上限。

同时删除两个客户端入口的 MAX_PLAYER_FONT_SCALE=2 截断；保留比例存储、0.75 最小值和响应式基准。客户端及本机服务验证有限数值与最小值，空输入允许编辑但不广播，无效值不持久化。刷新、重连不得重新截回 200%。

重排时保持同一阅读字符，再由播放端测量新范围；播放中重设计时基点继续，暂停时也更新高亮。字号变化不要求控制端同步字体。清理被最终 CSS 覆盖的死变量只限必要处。1000% 时测试 Latin 长单词/URL 的 `overflow-wrap`，不得出现正文横向溢出。

## 验收标准

- [ ] 缓存先行：2 万字符稿的连续报告/滚动不重复 TreeWalker 全文；编辑、节点替换、恢复稿件使旧映射失效，纯位置和覆盖层绘制不使其失效。布局变化正确重测，连续 10 分钟无持续卡顿或无限上报。
- [ ] 行范围：中文、英文空格、标点、全角、emoji/组合字素、重复段落、软/硬换行、标题、粗斜体、链接、代码、列表准确映射，装饰不计入。必须包含行边界非朗读字符、纯标点/emoji 行；近似边缘扩展失败时记录第二阶段阻塞，不能勾选精确对应。
- [ ] 行选择：中线在行间、空行、稿首尾时稳定；混合字号不拆错行。控制端高亮跨 2–3 行保持完整，横线落在字素最多的本地行，平局稳定；本地改宽度无需远端新消息即可重算。
- [ ] 编辑/完成：同一富文本实例切换不改变正文排版、不重置撤销栈；完成态不允许输入、粘贴、剪切修改或 directive 弹窗修改，无 caret。同步编辑态有高亮/横线；未保存改动隐藏两者并提示未同步，撤销回同步稿可恢复。原文切换单独核验，不把原文当渲染字符索引。
- [ ] 保存：完成替代独立保存草稿；无改动不打断播放；IME、待确认浮层、断线/失败、重复点击不丢字。有改动清空时钟，旧修订报告失效，无法重锚定时明确提示重新定位。
- [ ] 点字：playing 向前/向后定位后按原速度继续，paused 保持暂停，frozen 不被解冻；不产生临时暂停、第一帧旧 offset、重复居中或速度重置。旧语音目标不得拉回位置。标点吸附跨行失败纳入第二阶段阻塞；拖选/空白/注释不误跳，基本键盘等价操作可用。
- [ ] 字号：两端超过 200%，覆盖 300%、500%、1000% 及实际正文 >200px；数字/A+ 超过滑块常用范围仍有效，保存/重连不截断，非法值不进入状态；长 Latin 单词/URL 无横向溢出。
- [ ] 布局与多端：1280×800、768×1024、390×844；水平/垂直/组合镜像；播放/暂停中的 resize、fullscreen、字号与字体加载；主副端尺寸差异、主端切换、断线重连、旧会话/修订/时钟报告不会污染高亮。
- [ ] 延迟目标 P95 ≤ 150ms：**单机双窗口、同一浏览器上下文**下采集至少 200 次真实换行，从独立测试探针看到播放端 DOM 换行的 rAF 到控制端覆盖层已提交并经过下一绘制帧（rAF 探针作为绘制完成时间的上界代理，精确屏幕呈现用录像复核）；时间用 `performance.timeOrigin + performance.now()`，先校验两窗口时基偏差并随结果报告，不能只量消息到达。跨设备不直接相减各机 Date.now/reportedAt/serverReceivedAt；可用同画面高帧率录像测双屏响应，单机结果不能冒充真实局域网结果。记录样本数、P95、丢失/乱序样本和测试环境。
- [ ] 自动化：类型检查、lint、既有 46 项 contracts 与新增范围/缓存/修订/点击测试；真实布局断言用预期字符集合与几何独立核对，不能只比较同一实现函数的两次输出。测试使用临时房间存储，不触及用户稿件。
