## 目标与范围

播放端中间视觉行显示哪些字符，控制端就为这些字符加底色，并随换行、字号和视口变化更新。控制端原指示线改为由本地高亮位置推导。中间稿件区增加「编辑 / 完成」切换：完成态不允许输入、没有编辑光标，点击正文字符可以把播放端定位到该字符所在行。移除当前字号放大的 200% 限制。

## 交互约定（本方案的默认选择）

1. 已有稿件进入房间时默认完成态；空稿进入编辑态。模式只影响当前控制端，不作为全房间编辑锁。
2. 编辑态保留现有富文本/原文切换、格式、标记、注释、撤销重做。点击正文用于编辑，不发送跳转。完成态显示只读渲染稿，收起原文输入与格式修改入口；标记/注释也不能绕过只读状态触发编辑。
3. 点击「完成」先结束输入法 composition 和未完成的标记/注释编辑，保存当前草稿；成功后进入完成态。保存中避免重复提交，失败保留文字和编辑态并显示错误。无改动时不重复保存、不清空播放时钟。「完成」不自动创建历史版本，原有版本保存继续保留。
4. 有改稿时沿用保存会暂停播放的语义：保存前取得旧阅读锚点，保存后只在能明确对应的正文位置恢复；当前位置被删改且无法对应时显示需要重新定位，不能把旧偏移套在新稿上或静默跳到文首。完成态可点击新稿重新定位，不自动恢复播放。
5. 完成态单击正文字符：将包含该字符的播放端视觉行放到中线并暂停，沿用现有 seek 的暂停语义；横向不会为了把单个字居中而改变排版。拖选复制、滚动、点击空白或注释不触发误跳；提供键盘可访问的定位操作，不把每个字变成 Tab 停靠点。
6. 多播放端布局不同时，以现有 `effectivePrimary()` 选出的主播放端为唯一高亮来源；副端继续按语义位置跟随。主端切换、离线、重连后等待有效新报告，不能混用两个屏幕的行范围。
7. 实时高亮的可信前提是两端使用同一份已同步稿。编辑未保存导致内容分叉时不套用旧高亮，也不抢走编辑光标/自动滚动；完成保存且收到新修订报告后恢复高亮。无主端或旧客户端不支持行范围时明确显示未同步状态，不伪造精确范围。

## 开发方案

### A. 完整字符范围与同步契约

- 在现有 `reading-position.ts` 中补充显示字符映射，复用 `RenderBundle`、块锚点和 DOM Range，不另建播放引擎。
- 建议行范围结构：`currentLine: { draftRevision, ranges: [{ anchorId, start, end }] }`，每个范围是对应 RenderNode 的原始显示 `text` 的半开 UTF-16 区间 `[start, end)`。保留标点、空格、大小写、全角字符及 emoji；不包含 Markdown 语法、列表自动序号、标记和注释。显式换行用于行边界，不画成可见字符。
- 使用块锚点 + 块内偏移，避免重复句子用全文 `indexOf` 找错位置。高亮区间端点不得拆开代理对或组合字素。语音跟随继续使用现有 normalized offsets，通过明确映射衔接，不能直接改变 `normalizeReadingText()` 的含义。
- 范围从播放端真实布局测量：优先选择中线穿过的正文视觉行；中线位于行间时取最近一行，距离相同按固定阅读顺序选择。空稿/没有正文时范围为空。混合粗体、行内代码字号不同时按同一行的垂直重叠/行带归组，不能只靠字符 rect 中点完全相等。
- 阅读中逐帧判定是否换行，但只在范围变化时立即发送 `playback.reportState`；已有周期报告承担状态校准。同一帧合并事件，保留最新结果，不能每帧广播整份 RoomState。
- 字号、容器宽高、全屏、字体加载、镜像、稿件重排后，在布局完成时重新采样；暂停状态也必须更新。DOM 映射按稿件修订缓存，几何按布局失效重建，不能每个滚动帧扫描全文每个字符。
- 本机房间服务补充新增范围/跳转字段的有限数值、区间顺序、边界、修订校验；校验来源设备/会话及事件顺序，丢弃过期修订与旧主端结果。复用已有 session、clientSeq、serverSeq、scrollClockId，避免无必要的新消息系统。
- `draftRevision` 必须绑定实际渲染成功的 bundle，而非仅收到新 RoomState 就提前标新版本。草稿恢复、保存和重连都清理失效范围；旧格式报告可以继续支持旧位置逻辑，但不得冒充新功能的准确高亮。

### B. 编辑/完成态与点击定位

- `ControlConsole` 增加明确的模式按钮；完成态复用 `RenderBundleView` 的正文，不显示调试头部/重复标记侧栏，使用中央稿件区现有样式。
- 编辑态保留现有 MDXEditor/原文编辑器；模式切换保留草稿、已存在的撤销栈和合理的滚动位置。优先保留编辑器实例，避免每次切换通过重新解析/挂载丢掉编辑历史。
- 「完成」的异步保存由 `RoomClient` 复用 `saveDraft()` 返回结果驱动；从当前 `onSaveDraft: () => void` 拆清完成动作的成功/失败契约，不能在请求成功前先切成完成态。
- 点击定位读取实际指针命中的文本节点及块内偏移，加入新的精确显示定位字段（如 `Anchor.displayPosition = { draftRevision, anchorId, offset }`），经现有 `playback.setScrollClock` 下发；播放端用同一显示映射找到包含目标字符的实际行。
- 点击标点、emoji、相同文本的不同段落均定位到正确位置；只使用 Y 坐标或段落序号不满足要求。跨浏览器命中可用现有 DOM Range 做几何回退，不新增依赖。
- 控制端收到播放端确认的新范围后再展示已定位结果；旧时钟的晚到报告不能把高亮拉回去。无有效主端时不显示已完成的跳转反馈。

### C. 高亮与指示线完全由本地渲染

- 按报告的块锚点与区间生成控制端 DOM Ranges，再用 `getClientRects()` 绘制不参与排版的底色覆盖层。覆盖层 `pointer-events: none`，不改变富文本结构、字符宽度或编辑选区。
- 高亮始终覆盖整个报告范围，即使该范围在控制端换成两行或更多行；绝不只高亮控制端自己的整行。
- 将高亮字符按控制端本地视觉行分组，按可见字素数量选择最多的一行，将原横线放在该行中心；并列时稳定选择阅读顺序较前的行。以字素计数，避免 emoji/代理对被重复计数；范围包含的空白可着色，但不凭无宽度字符决定主行。
- 移除指示线的远端 `lineFraction`、滚动比例/高度回退及 slider 拖动职责；横线只展示本地高亮位置。控制端窗口变化或本地滚动时重新计算位置，不向播放端反向发送滚动命令。
- 完成态沿用必要的自动跟随，使高亮进入可视区；编辑态和用户主动拖选时不抢滚动。不要用高亮动画插值成播放端没有报告过的字符。
- 项目仍要求 Safari/iPad Safari 15；方案以 DOM Range + 覆盖层为基础，不把较新 CSS Custom Highlight API 作为必需条件。

### D. 取消字号放大上限

- 同时处理 `room-client.tsx` 的两个 clamp 函数、控制端输入、播放端 A+/A−、房间设置保存/加载及重连。
- 保留当前比例存储和响应式基础字号，移除 `MAX_PLAYER_FONT_SCALE=2`。最小值沿用 0.75，不新增任意的 300%/500% 产品上限。
- 固定上限 range 改为可输入的百分比数值控件，保留 A+/A−，明确单位；输入空值/非法值时允许正常编辑但不广播无效设置。客户端和服务端均验证有限正数及既有最小值。
- 使用同一阅读字符保持位置，再由播放端重新排版、报告新的整行范围。高亮范围可以随字号变化而变化；控制端文字不需要与播放端等字号或等换行。
- 清理当前 `--player-font-size` 与最终响应式 CSS 的口径歧义时仅做必要修改，不顺带重做显示样式。

## 验收标准

- [ ] 内容精确：中文、英文空格、标点、全角字符、emoji/组合字素、重复段落、软换行/硬换行、标题、粗斜体、链接、行内代码、列表均按播放端真实视觉行高亮；标记/注释/自动序号不计入。
- [ ] 换行跟随：播放、手动滚动、跳转、暂停均正确；正常局域网前台测试中，从主端实际换行到控制端显示的目标 P95 ≤ 150ms，且收到有效报告后下一个渲染帧更新。记录实测设备和网络；这是验收目标，非已验证结论或零延迟承诺。
- [ ] 行边界：中线落在行间、标题与正文之间、空行、稿首稿尾时选择确定且不抖动；混合字号不把同一行拆成多行。
- [ ] 控制端跨行：同一高亮范围在控制端分成 2–3 行仍完整着色；横线落在字数最多行，平局规则稳定；控制端改宽度无需等播放端另发消息即可重算横线。
- [ ] 编辑/完成：完成态无法输入、粘贴、剪切修改或通过标记弹窗改稿，无编辑光标；编辑态可正常输入、IME、撤销重做；切换不丢文字与历史。
- [ ] 保存：请求失败/断线/重复点击仍保留编辑内容；未修改点完成不打断播放；有修改按修订同步，旧范围失效，不能用旧偏移定位新稿。被删除的目标位置有明确重新定位反馈。
- [ ] 点字定位：完成态点击行首、行中、行尾、标点及 emoji，主端目标字符所在行进入中线并暂停；拖选复制、空白、注释点击不误跳；有键盘可访问方式。
- [ ] 字号：控制端与播放端都可超过 200%，覆盖 300%、500%、1000%（含实际正文 >200px），保存/刷新/重连后不被截回 200%；放大和缩小后字符保持、行范围重算；非法数值不进入房间状态。
- [ ] 布局矩阵：至少 1280×800、768×1024、390×844，水平/垂直/组合镜像，播放中与暂停时 resize/fullscreen/字号调整；字体加载导致重排也更新。
- [ ] 多端与时序：不同尺寸主副播放端、主端切换/离线、断线重连、旧会话/旧修订/旧时钟报告不得污染高亮；不支持新协议的端有明确降级状态。
- [ ] 性能：长稿（至少 2 万字符）连续播放 10 分钟，不因逐帧全文测量产生持续卡顿、布局抖动或无限上报；确认映射/几何缓存按正确条件失效。
- [ ] 自动化通过：类型检查、lint、现有 46 项 contracts 及新增字符范围/版本/点击测试；扩展 `reading-browser-smoke.mjs` 的真实布局断言，用预期字符集合和 DOM 几何作验证，不能只把同一个函数的输出与自己比较。
- [ ] Safari/iPad Safari 实机验收；当前仅 Chrome 的 smoke 不能替代 Safari 15/移动设备验证。浏览器测试使用独立临时房间存储，不接触现有用户稿件。
